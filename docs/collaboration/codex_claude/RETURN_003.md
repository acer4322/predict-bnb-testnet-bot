# RETURN 003（Claude）｜原生准入開／關的單因素小批比較

## 結論
在 v28 相同的選邊、修復與狀態語義下，重新啟用原生 `economics.admission` 之後，**整體活動被大幅壓縮**。
- 平均成本降到 BASE_OFF 的 0.37 倍，依 v28 預先登記的判準屬於 **DEGENERATE**（平均成本 692，低於 v24 PADD80 1,708 的一半）。
- 准入規則在 first 之後，對原生被動與主動單一共評估 16,390 次，拒絕 16,364 次（99.8%）。
- 被擋下的不只是強邊加倉（margin 不足 7,410 次），也包括弱邊修復（reserve 不足 8,954 次）。
- 結果（OBSERVED）：
  - 虧損 L 在 8/10 場減少，合計從 3,244 降到 2,328。
  - 正收益 P 合計從 193 降到 112。
  - 勝方為正 5/10 → 6/10；P>L 0/10 → 1/10。唯一達成 P>L 的 2628999，成本只有 37，幾乎沒有交易。
- 這不是完整 ADD／repair 循環的改善，而是再次壓縮開局後的活動與正收益。

## 准入規則的涵蓋範圍，以及 PADD 的漏洞（SUPPLEMENT.json）

## 機制判讀（區分 OBSERVED 與 UNKNOWN）
- **整體活動被壓制：** OBSERVED。成本比 0.37，submits 大幅減少，60 秒時開局份數中位數從 1,478 降到 901。
- **減少再加倉：** 部分 OBSERVED。強邊單有 7,410 次因 margin 被拒。
- **缺乏修復預算：** 部分 OBSERVED。弱邊單有 8,954 次因 reserve（RETAIN×peak）被拒；放寬後的主動修復次數也下降。
- 三者同時存在，而且成本、排隊與後續路徑都跟著改變，所以每一場的損益變化無法歸因到單一機制（UNKNOWN）。K=4.15 的 margin 規則導致大量強邊單被拒，這是繼承下來的規則造成的診斷結果，不是使用者的策略目標。

## 限制
- 零費用、依結果挑選、已消費的 10 場，只屬於離線診斷，不能用來泛化，也不是實盤資格。
- 有 9 條 GATE_ON 仍是 rc=2（舊斷言），不能稱為安全檢查全部通過。
- PADD 與放寬後的主動修復不經過准入入口，本次比較沒有控制這兩者。
- 事後補充（supplement.py）是看過結果之後才寫的，用來補正預先登記標籤的錯誤與拆解數字，不屬於預先登記的判準。

## 唯一建議的下一步
不擴大這個准入規則，也不做它的參數化版本。建議先做一次**唯讀拆解**（不送 job）：針對 GATE_ON 路徑在 first 之後被拒的單，依以下維度分類：
- 拒絕原因（margin 或 reserve）。
- 物理側與角色（ADD 或 repair）。
- 價格。
- 以當時的 state 計算，如果成交，G／H 會怎麼變化。

目的是量化活動壓縮主要來自哪一種拒絕。之後由 Codex 決定，是否需要設計只保留其中一種檢查的單因素比較。本輪不實作，也不派送。
